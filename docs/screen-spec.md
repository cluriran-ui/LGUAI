# 화면 명세

- 작성 관점: 도그냥(서비스 기획)  
- 자료 우선순위: PRD.md > screens.md > 화면 링크 > Make 링크 > flow.png (reference/links.md)  
- 표시 규칙: `[PRD 우선]` = screens.md와 PRD.md가 달라 PRD.md를 따름, `확인 필요` = 원본에 정의되지 않음  
- 라우트(화면 주소): 화면마다 붙는 고유 주소. 예: `/plans`  
- 개인정보 보호: 시안 속 이름·이메일 값은 옮기지 않고 `(이름 입력값)`, `(이메일 입력값)`으로 바꿔 적음

## 전체 요약
| 순서 | 화면 이름 | 라우트(화면 주소) | 한 줄 역할 |
|---|---|---|---|
| 1 | 요금제 목록 | `/plans` | 데이터량·소진 후 속도·매달 내는 금액을 카드로 비교해 후보를 고르게 함 |
| 2 | 요금제 상세 | `/plans/[id]` `[PRD 우선]` | 매달 내는 금액·할인 종료 후 금액·소진 후 속도를 확인하고 신청으로 넘어감 |
| 3 | 구독 신청 | `/apply` `[PRD 우선]` | 신청 정보를 입력받아 구독 신청을 저장함 |
| 4 | 신청 완료 | `/complete` `[PRD 우선]` | 저장된 신청 내역을 보여줌 |

이동 흐름: 요금제 목록 → 요금제 상세 → 구독 신청 → 신청 완료  
되돌아가는 흐름: 요금제 상세 → 요금제 목록("뒤로"), 구독 신청 → 요금제 상세("취소") (PRD 3, flow.png)  
- `[id]`: 요금제 번호(p01 ~ p04)가 들어가는 자리. 예: `/plans/p03` (PRD 4장 요금제 데이터)
