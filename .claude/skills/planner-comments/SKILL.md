# planner-comments — 기획자용 한국어 주석 달기

## 목적
- 화면 코드에 기획자도 읽을 수 있는 한국어 주석을 추가함
- 주석마다 해당 기획 항목(PRD.md·screens.md)을 연결하여 "이 코드가 어떤 기획을 구현하는지" 바로 확인 가능하게 함
- 코드 동작은 바꾸지 않고 주석만 추가함

## 입력
- `$ARGUMENTS`: 주석을 달 파일 또는 폴더 경로 (여러 개 가능)
- 경로가 비어 있으면 작업을 시작하지 않고, 어떤 파일에 주석을 달지 사용자에게 먼저 질문함
- 함께 읽는 기획 문서
  - `docs/PRD.md`: 화면별 기능, 유저 스토리(US1 ~ US5), 오류 문구, 판정 규칙
  - `docs/screens.md`: 화면 구성 요소와 이동
  - 두 문서의 내용이 다르면 `reference/links.md`의 우선순위(PRD.md > screens.md)를 따름

## 작업 순서
1. 대상 확인
   - `$ARGUMENTS`에 적힌 파일·폴더만 대상으로 삼음. 폴더면 그 안의 화면 파일만 포함
   - 경로가 없으면 질문 후 대기
2. 기획 문서 읽기
   - `docs/PRD.md`, `docs/screens.md`를 먼저 읽음
   - 화면 이름·라우트(화면 주소)·기능 번호(예: 4-3)·유저 스토리 번호를 정리
3. 코드 읽기
   - 대상 파일마다 어떤 화면인지, 화면 덩어리(헤더·카드·필터·입력란·버튼·하단 영역 등)가 어디인지 파악
   - 각 덩어리를 2번의 기획 항목과 짝지음. 짝이 없거나 내용이 다르면 `[확인 필요]` 후보로 표시
4. 주석 초안 작성 (파일에는 아직 넣지 않음)
   - 파일 맨 위: 화면 요약 주석 1개 (무슨 화면인지, 들어오는 곳·나가는 곳, 관련 유저 스토리)
   - 화면 덩어리마다 주석 1개 (무엇을 보여주는지, 누르면 어떻게 되는지, 기획 근거)
5. 초안 보여주고 승인받기
   - 파일별로 "어느 줄 위에 어떤 주석이 들어가는지"를 표로 보여줌
   - 사용자가 승인하기 전에는 파일을 수정하지 않음. 수정 요청이 오면 초안을 고쳐 다시 보여줌
6. 주석 넣기
   - 승인된 주석만 원래 코드 파일에 직접 넣음
7. 끝났는지 확인 → 아래 "완료 확인" 수행
8. 결과 보고 → 아래 "결과 보고" 형식으로 대화창에 정리

## 주석 형식
- 모든 주석은 `[기획]`으로 시작하여 개발자 주석과 구분함
- 파일의 언어에 맞는 주석 기호를 사용함
  - 일반 코드: `// [기획] ...`
  - 화면 마크업(JSX 등) 안: `{/* [기획] ... */}`
  - HTML: `<!-- [기획] ... -->`, CSS: `/* [기획] ... */`
- 기획 근거는 주석 끝 괄호에 적음
- 예시

```tsx
// [기획] 요금제 목록 화면: 요금제 4개를 카드로 보여주고, 카드의 '자세히'를 누르면 상세 화면으로 이동함
// [기획] 관련: PRD 4-1 · screens.md 요금제 목록 · US1 ~ US4

{/* [기획] 신청하기 버튼: 이름·휴대폰 번호·동의를 모두 채워야 눌림 (PRD 4-3 · US5) */}

// [기획][확인 필요] PRD는 휴대폰 번호를 받지만, 코드는 이메일을 받음
```

## 꼭 지킬 것
- 코드 보호
  - 주석만 추가함. 코드 내용·순서·들여쓰기·띄어쓰기·줄바꿈은 그대로 둠
  - 주석을 넣은 뒤에도 화면이 똑같이 동작해야 함
  - 기존 주석은 지우거나 고치지 않음
- 말투와 용어 (팀 문서 규칙)
  - "~함", "~임", "~됨"처럼 명사형으로 짧게 끝냄
  - 개발 용어는 쓰지 않음. 예: "상태값" → "지금 고른 조건", "렌더링" → "화면에 보여줌"
  - 꼭 필요한 용어는 쉬운 설명을 덧붙임. 예: `라우트(화면 주소)`
  - 약어는 풀네임과 설명을 함께 적음. 예: `CTA(Call To Action, 행동 유도 버튼)`
- 기획과 코드가 다를 때
  - 코드는 고치지 않음
  - 주석에 `[기획][확인 필요]`를 붙여 무엇이 다른지 적음
- 길이와 개인정보
  - 주석 한 줄은 120자 이내. 길면 여러 줄로 나눔
  - 실제 고객 이름·전화번호·이메일 등 개인정보는 주석에 넣지 않음. 코드에 들어 있어도 옮겨 적지 않음
- 범위
  - 지정한 파일 외에는 수정하지 않음
  - 별도 정리 문서는 만들지 않음

## 완료 확인
1. 코드 그대로인지 확인
   - 주석을 넣기 전과 후를 비교하여, `[기획]` 주석 줄을 뺀 나머지에서 바뀐 줄이 0개인지 확인
   - 비교 방법: 작업 전 원본을 임시 폴더에 복사해 두고 비교 (git 저장소면 `git diff` 사용)
2. 화면이 잘 열리는지 확인
   - 프로젝트에 검사 명령(빌드·타입 검사·린트 등)이 있으면 실행하여 통과 여부 확인
   - 검사 명령이 없으면 "확인 못 함"으로 보고. 실행하지 않은 검사를 통과로 보고하지 않음
3. 빠진 곳이 없는지 확인
   - 대상 파일마다 맨 위 화면 요약 주석이 있는지 확인
   - 파일별 `[기획]` 주석 개수를 셈

## 결과 보고
대화창에 아래 내용을 정리함.

| 파일 | 맨 위 요약 | [기획] 주석 수 | [확인 필요] 수 |
|---|---|---:|---:|
| (파일 경로) | 있음 / 없음 | 0 | 0 |

- `[확인 필요]` 항목 목록: 파일·위치·다른 점
- 확인 결과
  - 코드 그대로: 통과 / 실패 (바뀐 줄 수)
  - 검사 명령: 통과 / 실패 / 확인 못 함 (실행한 명령과 결과)
  - 빠진 곳: 없음 / 있음 (파일 목록)
